## Motivation

Two arcs converge in this release:

1. **The crypto layer is what production actually runs.** Ijima, Dominic, and
   tsukoshi ride on `src/crypto.rs`, not on the geometry. The 2026-09-12 dive
   found its *cryptography* disciplined (`verify_strict`, canonicalized,
   nonce-hardened, ADR-specified) but its *composition* unrigorous: the
   verify→may invariant held by caller discipline rather than types, a
   signature-ambiguity in NUL-terminated signing messages, three integer
   widths for one concept, panicking verifier constructors, and an audit
   subsystem blind to the token lifecycle. These are CVE-shaped, not
   paper-shaped.
2. **#17's instrument has an honest additive baseline begging for an
   engine.** Genuine non-additivity must come from boundary/singularity
   structure — Thatch's subject. Its S0/S2 probes are the cheapest path to
   the interaction term.

## Workstream A — Crypto-layer rigor (production track)

All items TDD (red test first). **ADR-0003** records the semantic
decisions (fallible constructors, NUL rejection, issuance validation,
VerifiedGrant); **ADR-0004** if audit hooks warrant their own record.

### A1 — `VerifiedGrant` proof type *(flagship)*

`verify()` returns `VerifiedGrant`; `may()` consumes `&VerifiedGrant`.
Delete the entire "no `may` without `verify`" bug class at zero runtime
cost using machinery the crate already stocks (`phantom.rs` re-exports
`GrantState` and `karpal_proof::Proven` — the door the 9/12 report found
closed).

- Additive API: bare `GrantVerifier::may(&grant, …)` kept, `#[deprecated]`
  with a doc note; new `VerifiedGrant::may(&self, …)`
- Ijima's privacy-based enforcement becomes a simplification, not a
  defense; Dominic's self-attestation-shaped routing line (federation.rs:173)
  becomes un-writable
- **Tests:** compile-fail (unverified grant can't reach `may`), doc tests
  on the new type, deprecation lint passes
- **Consumers:** Ijima + Dominic follow-up PRs in their repos (simplify +
  migrate)

### A2 — Reject NUL in `PrincipalId` / `CapabilityId`

`new()` returns `Result` rejecting interior NULs (and the empty string).
Closes the re-split signature ambiguity (report §2.3) — "the two-line CVE
fix". Breaking (0.x-sanctioned).

- **Tests:** constructor accepts valid, rejects `a\0b`, rejects empty;
  issuance roundtrip never produces ambiguous signing messages; policy
  path unchanged (TOML already forbids control chars)

### A3 — Partition validation at issuance

`issue_grant*` validates before signing: components and length fit `u8`
(report §2.4's three-widths landmine), plus monotonicity and part count
where a Grassmannian context is available. Policy path already bounds
these — this arms the raw path too.

- **Tests:** `[300]`-style truncation impossible (rejected, never
  silently signed as `[44]`); length bound; `may`/verify agreement
  guaranteed on every issued token

### A4 — `Result` from verifier constructors

`GrantVerifier::new` / `CapabilityVerifier::new` return `Result` instead
of `expect`-panicking on malformed keys (report §2.5). Breaking, cheap.

- **Tests:** 31-byte key → `Err`, not a process death

### A5 — Token lifecycle audit hooks

Decide + implement: issuance, expiry denial, policy denial, revocation
checks emit audit events (report §2.5's "invisible layer"). Design leans
on existing `audit.rs` async/fail-open semantics — injected sink or event
emission at verify/issue sites.

- **Tests:** each lifecycle event recorded; fail-open behavior preserved

### A6 — tsukoshi parity

One parity PR mirroring A2/A3 validation in the TS issue paths
(NUL/width/monotonicity rejection + fixtures). `VerifiedGrant` is
compile-time only — TS gets a branded-type doc story in ADR-0003, no
runtime change.

**PR slicing (suggested):** A2+A4 (constructor rigor, one PR) → A3 → A1 →
A5 → A6. Consumer touch-ups (Ijima, Dominic) land the same week as A1/A2.

## Workstream B — Research arc: Thatch → #17 (edge track)

Independent start; lives mostly in the Thatch repo.

### B0 — Thatch logistics

Forgejo mirror + GitHub remote (`/skill:ia-forgejo-mirror`); gitflow from
the first pushed branch.

### B1 — Thatch S0: strata substrate

`strata(partition) -> Poset` — boundary/singular-stratum combinatorics for
all Schubert varieties in Gr(2,4) and Gr(3,6), from partitions alone
(known Kazhdan–Lusztig/Bott–Samelson data). Zero new math; the substrate
every later probe reads. Hand-checked test cases.

- **Exit:** thatch `0.1.0` published to crates.io (tiny surface — strata
  module only) so Schubert can depend on it cleanly

### B2 — Ω↔stratum dictionary (Thatch S2)

Map Karpal's `IntersectionKind` values (structural zero / geometric zero /
granted-n / granted-∞ / underdetermined) to boundary-stratum classes;
exhaustiveness test against B1's computed strata. Holes ⇒ Ω needs
extension; collapse ⇒ Ω redundant there. Either result is a result.

### B3 — Schubert #17: the interaction term

Feature `thatch` (additive) feeding `analyze_composed_stability` /
wall-crossing engine a strata-overlap signal: composed principals whose
surfaces share boundary strata.

- **Success criterion (honest either way):** the first documented genuine
  non-additive breakpoint, **or** a validated proof of additivity under
  the current scope — both advance #17
- Interim `git` dep acceptable until B1's crates.io publish; ship behind
  the feature flag regardless

## Workstream C — §4 design record (per operator decision)

### C1 — ADR: Geometry-Typed Grants

The design record for `GrantToken<G: Geometry = Unspecified>` —
default-type-param back-compat, verifiers typed by geometry (a Gr(2,4)
verifier statically unable to accept a Gr(4,8) token), karpal-schubert-types
integration, the tsukoshi story (branded types / runtime geometry check —
phantom types don't cross), Dominic mixed-geometry federation
implications, migration path. Scope: **design only**; implementation is
the v0.8.0 headline with #18.

### C2 — Experimental spike

Behind a `geometry-typed` feature: minimal compile-proof of the typing
(type-level geometry tag; verifier rejects foreign-geometry token at
compile time). Doc tests only, no federation semantics, additive-only.
