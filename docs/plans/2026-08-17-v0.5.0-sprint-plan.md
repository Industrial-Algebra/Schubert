## Workstream A — `GrantToken` expiry & nonce (#20.1) — the sprint spine

Spec source: ROADMAP #20.1 + ADR-0001. TDD throughout; no new feature gates (all under
existing `crypto`).

1. **Rust core**
   - `GrantToken` gains `expires_at: Option<u64>` (Unix seconds, signed) and
     `nonce: [u8; 16]` (random at issue, signed, *not* in the capability sort).
   - `issue_grant` defaults (`nonce` random, `expires_at` None);
     `issue_grant_with_expiry(...)`; test-injectable nonce for determinism.
   - `GrantVerifier::verify_at(grant, now_unix)` (clock-injected; `verify` delegates via
     `SystemTime::now`). Expired ⇒ same error class as bad signature.
   - Wire format: extend `to_bytes`/`from_bytes` (breaking layout OK per ADR-0001;
     Ijima re-mints).
   - Test matrix (from the spec): round-trip future/past expiry + `verify_at`
     determinism; distinctness (two identical inputs ⇒ different bytes, both verify);
     tamper (flip expiry/nonce ⇒ sig failure); sort stability under nonce randomness.
2. **tsukoshi parity** (`./crypto` subpath)
   - Mirror fields + wire format; update `wire.ts`.
   - Cross-language fixtures BOTH directions: Rust-issued ⇒ TS-verified and
     TS-issued ⇒ Rust-verified, exercising expiry and nonce paths (extends the
     `tsukoshi_crypto_vectors` example).
3. **Docs**: `book/src/api/crypto.md` wire-format section; `book/src/api/axum.md` note
   (extractor rejects expired via `verify`); CHANGELOG entry.

**Exit criteria:** full CI matrix green (all six feature combos + `--all-features`),
tsukoshi `npm run build && npm test` green, cross-language fixtures land in both repos.

## Workstream B — grant-aware revocation + policy linkage (#20.2, #20.3)

Prerequisite: **ADR-0002** (decision: upgrade `CrdtGrant` to carry a grant id vs.
tombstone registry keyed by grant hash) — decide *before* code, half a page like ADR-0001.

1. **#20.2 Grant-aware CRDT revocation** — implement the ADR-0002 choice in
   `src/crdt.rs`; parallel treatment for tsukoshi `GrantCRDT` (add-wins semantics
   revisited: revoke must beat a *concurrent re-grant of the same grant id*, or
   tombstones must — the ADR settles which).
2. **#20.3 Policy → issuance linkage** — connect `from_policy_toml` (#3) to
   `CapabilityIssuer`: policy.toml constrains *what grants may be issued*
   (constrained issuance) so Ijima can own policy while principals carry grants.
   Surface: an issuance-check fn the controller path and raw issuing share.

**Exit criteria:** convergent-revocation property tests (multi-replica, interleaved);
policy-constrained issuance tests including deny cases; tsukoshi parity where applicable.

## Workstream C — #17 wall-crossing follow-through (small, parallel)

1. **Roadmap staleness fix** (folded into this PR): #17's cross-link says the probe is
   "in flight (PR #37, CI-green)" — update to **landed** (`analyze_composed_stability`).
2. **Non-additivity probe example** (`examples/` or book): exercise

## Sequencing

```
Week 1:  A (Rust core → tsukoshi parity → fixtures)   ├─ C1 roadmap fix (this PR)
Week 2:  A docs/CHANGELOG → B ADR-0002 → B code       ├─ C2 probe example
Wrap:    version bump PR → release/v0.5.0 branch (date CHANGELOG) → main →
         tag v0.5.0 → crates.io + npm tsukoshi → main→develop backmerge → announce
```

Workstream A first: it unblocks Ijima 0.5 and is fully spec'd. B starts with its ADR
(in-flight while A's tsukoshi parity runs). C is opportunistic.

## Verification & release gates

- The standard CI matrix (`fmt`, `clippy --all-targets --all-features -D warnings`,
  tests across all feature combos, `cargo doc` zero broken links).
- tsukoshi: `npm run build && npm test`; cross-language fixture vectors regenerated.
- Release per gitflow (`AGENTS.md`): bump → PR; release branch dates the changelog;
  tag triggers crates.io; `npm publish` tsukoshi; **backmerge `main → develop`
  (merge commit)**; announce via `/skill:ia-website`.
- "Shipped" = crates.io + tag + npm + backmerge done.

## Out of scope (explicit)

- Any KS-type *proof* for #17; flag-variety embedding (#18); GPU acceleration (#19).
- A renewal/rotation protocol (ADR-0001 rule 4: re-issue is the pattern).
- Skew-tolerance fields in the token (rule 3: verifier's concern).
